它是怎么工作的

四步，全自动。

1

取景

相机实时预览，对准要核对的内容

2

拍摄

手动点快门、自动每秒一帧，或切「流式分析」连续推帧

3

识别

ML Kit 把画面里的文字逐行读出来

逐行和表格比，命中项高亮打勾

界面上会看到什么

左上角是当前状态，右上角是正在使用的数据集，中间浮层是比对结果（分界线之上先列命中项，之下是全部识别结果）。

左上角显示含义
对准目标，等待识别空闲，或刚点过「重拍」
正在识别文字…正在识别，还没有历史结果
命中 3 / 20（更新中…）正在识别下一帧，画面里是上一帧的结果
命中 3 / 20识别完成，命中 3 行
命中 3 / 20（画面未变）这一帧和上一帧一样，直接复用了上次结果（省一次识别）
无命中 · 20 行识别到 20 行，但没有一行在表格里
没识别到文字画面里确实没有可识别的文字
OCR 识别失败识别引擎出错（和「没文字」是两回事）
命中 X / Y 里的 Y 是「这一帧识别到的行数」，不是表格条目数。 表格有多少条看右上角那个胶囊。

命中行的颜色分三种：绿色 = 完全相同， 黄色 = 近似（包含关系或模糊匹配，末尾会标出「近似 83%」）， 蓝色 = 你在表格里手动标记过「已识别」（优先级最高）。 一眼能看出这个命中是什么情况。

数据集格式

一行一个关键词。点右上角的胶囊进入管理页，可以选文件导入，也可以直接粘贴。

# 以 # 开头的是注释行，会被跳过
Serial Number
Model
Manufacturer, Mfg, Maker
Production Date
规则说明
一行一个条目这一行的内容就是关键词
逗号 / 制表符 / 分号第一个是名称，其余当别名：上面例子里 Mfg、Maker 都算命中 Manufacturer
空行与 # 注释跳过，不算错误
两侧空白与 CSV 引号自动去掉，"Serial Number" → Serial Number
名称重复合并别名，不会产生重复条目
Excel 导出的 CSV 默认是 GBK 编码，不是 UTF-8。直接用 UTF-8 读会全是乱码， 所以 App 会按 UTF-8 BOM → UTF-8 → GBK 顺序自动探测， 导入预览页会把识别到的编码显示出来，一眼能确认。

导入一定会先进预览页：解析出多少项、前几项长什么样、编码是什么、跳过了几行——确认无误才落盘。 这一步是故意的，格式不对当场就能看出来，不会白白导入一堆垃圾数据。

比对是怎么做的

三层策略，从严格到宽松。

层规则例子
1完全一致（归一化之后）Serial Number: = serial number
2包含：识别行里含某个表格项Serial Number: A12345 → Serial Number
3模糊：编辑距离容忍字母错认Manufacterer → Manufacturer

比对之前先做归一化：转小写、全角转半角、只保留字母/数字/汉字，丢掉所有空白和标点。 所以 Serial Number:、ＳＥＲＩＡＬ　ＮＵＭＢＥＲ 会被当成同一个。

为什么门槛不能一刀切

英文单词很短，改一个字母往往就是另一个词，所以用相似度阈值会出事：

  • 长度少于 5 个字母的词不参与模糊匹配（date 和 rate 只差一个字母）
  • 5~6 个字母容忍 1 处差异，7~10 容忍 2 处，11 个以上容忍 3 处
  • 包含关系只认一个方向——识别行包含表格项才算命中。反过来算的话，Rate 会因为落在 Rated Voltage 里而误命中

安装

下载 APK 直接装，不需要 root，不需要任何权限之外的东西。

  1. 点 下载最新 APK（文件名叫 recognizer-<版本>-debug.apk）
  2. 手机上点开它，系统会提示「允许安装未知应用」，同意即可
  3. 首次打开会申请相机权限——识别需要它，除此之外没有其他权限
这是 debug 签名的构建（用 Android 默认调试密钥签名），仅供自己安装体验， 不适合上架应用商店或对外分发。构建流程里缓存了调试密钥，所以后续版本可以直接覆盖升级； 但缓存在长期无访问后被清理时会换密钥，届时需要卸载重装（卸载会清掉相册和数据集）。

所有数据都存在 App 私有目录里，卸载即清除。想清理相册可以在相册页点「清空」。

构建

用 Android Studio 直接点 Run 即可（它自带的 JBR 就是 Java 25）。命令行必须显式指定 JDK 25：

JAVA_HOME="$HOME/下载/android-studio/jbr" ./gradlew :app:assembleDebug
如果报 Unable to download toolchain matching the requirements ({languageVersion=25, ...})， 就是 JDK 版本不对——Gradle 正试图从网上拉一个 Java 25 工具链。把 JAVA_HOME 指到 25 即可。

DatasetParser 刻意和 DatasetStore 分开：解析全是纯函数、不碰 Context， 所以能直接在电脑上跑单元测试。

已知限制

  • 只识别拉丁文（英文 + 数字）。需要中文得换成中文模型依赖。
  • 相册只存预览图（480px 宽），点开看大图会糊——这是为了不把十几 MB 的原图堆在手机里。
  • 表格是单列关键词，不支持「字段名 + 标准值」的取值校验。
  • 不解析 HTML，导入 HTML 会把标签当成关键词（预览页能看出来）。
  • 没有导出功能，卸载 App 会清掉相册和数据集。

常见问题

需要联网吗？会上传我的照片吗？

完全不需要联网，也不会传任何东西。识别模型是随 APK 一起打包的，照片、识别结果、表格全部只存在手机本地。飞行模式下功能完全正常。

为什么 APK 有 55 MB？

主要是 ML Kit 的 native 识别库，而它同时打包了 4 种 CPU 架构（arm64 / armv7 / x86 / x86_64），这一项就占 42 MB。实际只需要 arm64 一个，但为了兼容性现在都带着。

装新版本提示「应用未安装」怎么办？

说明新旧两个包的签名不一致。先卸载旧的再装（注意：卸载会清掉相册和数据集）。这种情况只会在签名密钥变化时出现。

为什么默认是手动模式？

手动更可控：只有按下快门那一下才识别。需要连续扫很多标签时，可以把底部的识别管线切到「流式分析」——相机会一直推帧、识别完立刻处理下一帧，而且它不看手动/自动开关，切过去就开始连续工作。

连续扫描会不会把相册撑爆？

不会。连续推帧（自动模式 / 流式分析）时相册按两条规则节流：画面和上次存过的完全一样就跳过、距上次存不足 3 秒也跳过。所以相册是「每 3 秒给当前画面拍一张快照」，不是每一帧都存——实测连续扫 53 秒只多 18 张。手动拍摄不受限制，每按一次快门都留一张。上限 200 张（约 8.8MB），超过后从最早的开始删。

识别不准怎么办？

让文字占满画面、光线均匀、手机端平（减少透视变形）都能明显提升准确率。另外只有和表格里某一项能对上时才会打勾——如果表格里的写法和你拍到的差太多，可以在表格那一行里用逗号补上别名。
