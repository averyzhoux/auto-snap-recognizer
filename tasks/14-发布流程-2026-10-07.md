## 起因：审查原 workflow

原 `release.yml` 有 7 处问题，按严重度：

| 严重度 | 问题 |
|--------|------|
| 高 | 叫「Release APK」，构建的却是 debug；而 `release` 构建类型**没有 signingConfig**，`assembleRelease` 只能产出 unsigned APK（装不上） |
| 高 | `versionCode` / `versionName` 硬编码 `1` / `"1.0"`，与 tag 完全脱节 |
| 中 | 不跑测试（项目有 33 个单测） |
| 中 | 没处理 Android SDK 许可（compileSdk 37 的 platform 靠 AGP 自动下载，前提是许可已接受） |
| 低 | 没有 Gradle 缓存；`cp *.apk` 通配符脆弱；没有手动触发 |

## 方案选择

讨论了「正式签名（keystore 走 Secrets）」和「保持简单」两条路，用户选：

> 「就只是 release 这种 debug 版本吧，不正式了，但是包名还是要改为 dev.averyzhoux.recognizer」

于是保持 debug 签名，但把配置补正确 + 明确标注。

## 做了什么

| 项 | 现在 |
|----|------|
| 单测闸门 | `testDebugUnitTest`，失败不出包 |
| 依赖缓存 | `cache: gradle` |
| SDK 许可 | 显式 `yes \| sdkmanager --licenses` |
| 版本号 | 从 tag 推导：`v1.2.3` → versionName `1.2.3` / versionCode `10203` |
| APK 路径 | 写死 `app-debug.apk`，不再用通配符 |
| 验签 | `apksigner verify --print-certs` |
| 手动触发 | `workflow_dispatch` |
| 诚实度 | Release 说明里明确标注是 debug 签名 |

`app/build.gradle.kts` 配套支持注入：

```kotlin
val injectedVersionName = providers.gradleProperty("versionName").orNull
val injectedVersionCode = providers.gradleProperty("versionCode").orNull?.toIntOrNull()
...
versionCode = injectedVersionCode ?: 1
versionName = injectedVersionName ?: "1.0"
```

**versionCode 规则**：`major*10000 + minor*100 + patch`（minor / patch 各 99 上限）。

## 自己第一版写出的两个 bug（已修）

1. **手动触发时 `GITHUB_REF_NAME` 是分支名**（如 `main`），`MAJOR * 10000` 会因非数字**直接报错** → 改成每段都做纯数字校验，兜不住就退化成 `0.0.<run_number>`
2. **手动触发时 ref 不是 tag**，`action-gh-release` 会**失败**（它要求 tag）→ 加 `if: startsWith(github.ref, 'refs/tags/')`，手动跑只上传 workflow artifact

## 最关键的一处：缓存 debug keystore

全新 runner 上 `~/.android/debug.keystore` 不存在，AGP 会**当场随机生成**一把。于是**每次构建的签名都不同** → Android 拒绝覆盖安装 → 必须卸载重装 → **相册和数据集全丢**（都在私有目录）。

加了一行 `actions/cache` 缓存这个文件，所有 CI 构建共用同一把调试密钥。

> 注意：GitHub cache 7 天不用会被清掉，清掉后签名会变，届时仍需卸载重装。要彻底避免只有正式签名一条路。
