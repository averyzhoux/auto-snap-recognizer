# 03 · 接入 ML Kit 识别图片文字

| | |
|---|---|
| **日期** | 2026-10-06 |
| **状态** | ✅ 已完成（模型已从中文换成英文） |
| **涉及文件** | `gradle/libs.versions.toml`、`app/build.gradle.kts`、`MainActivity.kt` |

## 目标

把抓到的帧识别成文字，显示在屏幕上。

## 做了什么

- 依赖：最初是 `com.google.mlkit:text-recognition-chinese:16.0.1`（**中文模型**）
- `InputImage.fromBitmap(bitmap, rotationDegrees)` 交给 ML Kit 摆正
- 状态机从 `CaptureStatus` 扩展成 `OcrStatus`：`Idle` / `Recognizing` / `Recognized` / `Failed`
- 结果面板：可滚动的文字区 + 「重拍」按钮

## 中途的需求变更：中文 → 英文

用户要求「不必识别中文了，只识别英文即可」，于是：

| | 中文版 | 英文版 |
|---|---|---|
| 依赖 | `text-recognition-chinese` | `text-recognition`（拉丁文） |
| 初始化 | `ChineseTextRecognizerOptions.Builder().build()` | `TextRecognizerOptions.DEFAULT_OPTIONS` |
| 效果 | 中英混排 | 英文 + 数字，模型更小、准确率更高 |

> APK 体积只从 56M 变成 55M：因为 42MB 是 `libmlkit_google_ocr_pipeline.so` 的 **4 个 CPU 架构**，模型资产的差异被淹没了。

## 关键决策

- 用 **bundled 版**（模型打进 APK）。代价是体积大，好处是**完全离线、不依赖用户设备上的 Google Play 服务版本**。
- **不自己旋转 Bitmap**，把 `rotationDegrees` 交给 `InputImage.fromBitmap()`，让 ML Kit 内部摆正，省一次全图矩阵运算。

## 踩坑

1. **中文必须用专用依赖**。默认的 `text-recognition` 是拉丁文模型，中文直接认不出来。这是本项目最初最容易踩的坑。
2. `TextRecognizer` 持有 native 资源（`libmlkit_google_ocr_pipeline.so`），**必须在页面销毁时 `close()`**，否则泄漏。
3. 识别回调不在主线程，但赋值 Compose snapshot state 是线程安全的，不需要 `runOnUiThread`。
4. 结果面板浮在预览上会挡住大半画面——当时记下留待后续 UI 优化。

## 验证

- logcat：`recognized 37 lines`（对着电脑屏幕，中英混排全部认出）
- 截图确认结果面板与文字滚动

## 遗留

`recognize()` 的失败回调当时把失败也当成「空结果」返回，导致 OCR 引擎真出错时会显示成「没识别到文字」。这个文案问题后来单独修了（见任务 15）。
