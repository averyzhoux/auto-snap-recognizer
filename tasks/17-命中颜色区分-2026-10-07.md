## 目标

> 需求原话：「相似用黄色，完全相同用绿色」

之前所有命中统一用小米黄，看不出这个命中是**精确对上**的还是**猜出来的**。

## 做了什么

新增一个颜色判定函数，两处渲染都走它：

```kotlin
private val MatchGreen = Color(0xFF3DDC84)

private fun matchColor(match: LineMatch): Color? = when {
    !match.isHit -> null          // 未命中：由调用方灰显
    match.isExact -> MatchGreen   // 完全相同 → 绿
    else -> XiaomiYellow          // 包含 / 模糊 / 别名 → 黄
}
```

| 颜色 | 含义 |
|------|------|
| 🟢 绿色 | **完全相同**（归一化后一致） |
| 🟡 黄色 | **近似**——包含关系或编辑距离模糊命中，末尾标出「近似 83%」 |
| 灰色 | 未命中 |

改动点：

- `MatchRow`（拍摄页结果面板 + 相册详情页共用）——勾、文字、高亮底色都按颜色走
- `CardLine`（相册纵览卡片）——原来接的是 `hit: Boolean`，改成接 `Color?`，因为"命中"现在有两种颜色
- 顺带删掉了原来写死的 `hitColor` 变量

## 验证

用户的真实数据集是「宝马展」（102 项，形如 `TH-6983`），相册里**全是近似命中（sim 0.833）、没有精确命中**——直接拍看不出绿色。

所以用了一次临时手段：

1. 在设备上**造一条相册记录** `000900.jpg/.json`，里面同时放一个精确命中（`TH-6802` → `TH-6802`, sim 1.0）和一个近似命中（`TH-6930` → `TH-6900`, sim 0.833）
2. **临时**在启动加载相册后自动打开这条的详情页（不用手点，绕开 MIUI 禁止 adb 注入触摸）
3. 装机截图 → 确认一绿一黄同时正确渲染
4. **移除临时代码 → 重新构建装机 → 删除造的那条相册记录**

还原后确认：无崩溃、`dataset loaded: '宝马展' 102 entries`、`gallery loaded 200 items`、启动停在拍摄页。
