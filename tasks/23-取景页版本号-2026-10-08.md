# 23 · 取景页底部显示版本号

| | |
|---|---|
| **日期** | 2026-10-08 |
| **状态** | ✅ 已完成，真机截图逐像素核对 |
| **涉及文件** | `app/build.gradle.kts`、`CameraControls.kt`、`MainActivity.kt`、`README.md` |

## 目标

> 需求原话：「把版本号显示在屏幕的最下边居中，用小字。」

格式 `v1.2.3 (10203)`，小字、半透明。

用处是**出问题时一眼确认手机上装的到底是哪个构建**——覆盖安装过好几个版本之后，
光看界面是分不出来的。

## 版本号是从哪来的

先回答当时问的「版本号依据在哪个文件」：

```kotlin
// app/build.gradle.kts
val injectedVersionName = providers.gradleProperty("versionName").orNull
val injectedVersionCode = providers.gradleProperty("versionCode").orNull?.toIntOrNull()

defaultConfig {
    versionCode = injectedVersionCode ?: 1        // ← 本地默认
    versionName = injectedVersionName ?: "1.0"    // ← 本地默认
}
```

- **定义处**：`app/build.gradle.kts` 的 `defaultConfig`，本地不传参就是 `1.0 / 1`
- **CI 注入**：`.github/workflows/release.yml` 从 git tag 推出来，再以
  `-PversionName=... -PversionCode=...` 传给 Gradle（`v1.2.3` → name `1.2.3` / code `10203`）
- **`gradle.properties` 里没有版本号**，别去那儿找

## 实现

### 1. 打开 BuildConfig

```kotlin
buildFeatures {
    compose = true
    buildConfig = true   // AGP 8 起默认不生成
}
```

运行时读 `BuildConfig.VERSION_NAME` / `BuildConfig.VERSION_CODE`——编译期常量，
不用走 `PackageManager`，也不用 try/catch。

### 2. 组件（`CameraControls.kt`）

```kotlin
@Composable
internal fun VersionLabel(modifier: Modifier = Modifier) {
    Text(
        // 就是把两个字段直接拼起来，不加也不去任何前缀
        text = "recognizer${BuildConfig.VERSION_CODE} ${BuildConfig.VERSION_NAME}",
        color = Color.White.copy(alpha = 0.35f),
        style = MaterialTheme.typography.labelSmall,   // 11sp
        maxLines = 1,
        modifier = modifier
    )
}
```

做得很淡（35% 白）：它只是兜底信息，不该抢取景画面的注意力。

#### 格式改过一版：不要多塞一个 `v`

最初按「`v<versionName> (<versionCode>)`」写成了
`"v${VERSION_NAME} (${VERSION_CODE})"`，改格式时**又在前面多加了一个字面 `v`**，
结果真机上显示成 `recognizer1 vv0.1.0dev2`——因为 `defaultConfig` 里的默认值
本身就已经是 `v0.1.0dev2`（带 `v`）。

现在的做法是**原样拼接，不碰前缀**：`versionName` 带不带 `v` 由配置决定，
代码里不再自作主张。这样不管以后默认值是 `v1.2.3` 还是 `1.2.3`，都不会拼出 `vv`。

> ⚠️ 顺带发现一处不一致：CI 从 tag 推版本号时会**把 `v` 剥掉**
> （`.github/workflows/release.yml`：`v1.2.3` → `versionName=1.2.3`），
> 所以将来发布版显示的是 `recognizer10203 1.2.3`，本地是 `recognizer1 v0.1.0dev2`。
> 要统一得改一处（默认值去掉 `v`，或 workflow 别剥），**目前没动**。

### 3. 放在哪

**压在屏幕最底边**——比系统导航键（`☰ ◻ ◁`）还低：

```kotlin
// 排在控件 Column 之后、when (screen) 之前：
//   - 在 Column 外面，才不会被 Column 的底部留白挡住
//   - 在 when (screen) 前面，翻相册/数据集时会被那些覆盖层盖住，只在取景页出现
VersionLabel(
    modifier = Modifier
        .align(Alignment.BottomCenter)
        .padding(bottom = 2.dp)     // ★ 不避让 navigationBars，就是要在导航栏那条带里
)
```

控件 Column 的 `padding(bottom)` 恢复成加版本号之前的 `18.dp`——版本号既然移出去了，
就没必要再为了给它腾地方而收窄。

**为什么不用「塞进 Column 最后一个子项」那套**（最初是那么写的）：那样只能落在导航栏
**上面**，而这个需求要的是屏幕最底边，必须越过 `navigationBars` 这道 inset。代价写在
[VersionLabel] 的 KDoc 里：换到**手势导航**时底部中间是那颗胶囊，会撞上。

## 验证

真机截图（1220×2712，density 520 → 1dp = 3.25px），逐像素量的：

| 项 | 实测 | 说明 |
|---|---|---|
| 文字位置 | y 2664..2699 → **距屏幕底 3.4~14.2dp** | 在系统导航键**下方** |
| 系统导航键 | y 2612..2658 → 距屏幕底 16.3~30.5dp | 两者间隙 2.1dp，**不重叠** |
| 文字未被裁 | 下沿距屏幕底还有 3.4dp | 完整可见 |
| 水平居中 | x 407..814，中心 610.5px vs 屏幕中心 610px | 居中 |
| 宽度 | 125.5dp | `Recognizer1 v0.1.0dev2` |
| 亮度峰值 | 92/255 ≈ **36% 白** | 对应 `alpha = 0.35f` |
| 字高 | 10.8dp | `labelSmall` = 11sp |

构建通过、33 个单测全绿、覆盖安装后启动无崩溃。

顺带确认了相机预览没被这次改动影响：截图里取景区不是纯黑（亮度 3~27、90+ 种颜色、
偏棕色），说明是**对着暗桌面**而不是预览坏了。
