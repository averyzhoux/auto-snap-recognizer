## 目标

> 需求原话：「com.example.recognizer，改为 dev.averyzhoux.recognizer」

`example` 是官方占位符，不该出现在要发布的包里。而且这是个**不可逆**的决定：一旦用某个包名发布了签名包，之后再改包名就是一个全新应用（用户要卸载重装、无法覆盖升级）。所以要改就现在改。

## 做了什么

| 改动 | 内容 |
|------|------|
| `namespace` + `applicationId` | 都改为 `dev.averyzhoux.recognizer` |
| 源码目录 | `java/com/example/recognizer/` → `java/dev/averyzhoux/recognizer/`（main / test / androidTest 三处） |
| 引用替换 | 14 个文件、18 处，含 `import ...ui.theme.RecognizerTheme` 和插桩测试里的包名断言 |
| 残留检查 | `grep com.example` 零命中，空的 `com/example` 目录已清理 |

`AndroidManifest.xml` 无需改动——Activity 用的是相对名 `.MainActivity`。

## 关键后果（必须知道）

**`applicationId` 变了，手机上原来那个 `com.example.recognizer` 就是另一个 App 了。**

- 新包会装成一个**全新的应用**，相册和已导入的数据集**不会跟过去**（私有目录按包名隔离）
- 两个包可以并存，桌面出现两个图标
- 手机上那个旧包后来被卸载了，它的相册和数据集也随之清空

## 提交注意

包名迁移在 git 看来是「14 个文件被删 + 新文件未跟踪」。**必须先 `git add -A`**（或 `git add app`）再提交，否则 `git commit -a` 会提交「删除所有源码」而不含新文件，仓库里就一个源文件都不剩。

`git add -A` 之后 git 会自动识别成 **rename**（内容相同），历史不会断。
