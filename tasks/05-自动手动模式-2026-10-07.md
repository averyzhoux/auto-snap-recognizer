# 05 · 自动 / 手动拍摄模式

| | |
|---|---|
| **日期** | 2026-10-07 |
| **状态** | ✅ 已完成（默认值后来改为手动） |
| **涉及文件** | `MainActivity.kt` |

## 目标

加一个控件，让用户选择手动拍摄还是每 1 秒自动拍摄。

> 需求原话：「先出一个可选的控件，来让我选择是手动拍摄还是每个 1s 自动拍摄，默认自动」

## 做了什么

- `autoMode` 状态 + `LaunchedEffect` 定时循环（间隔 `AUTO_CAPTURE_INTERVAL_MS = 1000L`）
- `AtomicBoolean busy` 保证同一时刻只跑一帧；识别慢了就顺延，不排队堆积
- **帧结果缓存**：对每帧算一个 32×32 的像素指纹，画面没变就复用上次的比对结果，省掉一次 ML Kit 调用
- 切换模式时清空缓存，避免手动模式看到自动模式的旧结果

## 关键决策

- **加帧缓存是为了消除闪烁**。1 秒一帧时结果面板会疯狂更新，加了缓存后画面静止时结果稳定。
- 指纹计算丢掉颜色低 3 位（`pixel and 0xF8F8F8`），避免一点点噪点就判定为「画面变了」。

## 踩坑（自动模式才暴露的真 bug）

```
ImageCaptureException: Not bound to a valid Camera
```

`bindToLifecycle()` 是**异步**的：`ImageCapture` 对象一创建就非空，但底层相机可能还要几百毫秒才真正打开。这期间 `takePicture` 会抛错。

手动模式下用户不会点那么快，所以一直没暴露；**自动模式第一帧必然失败**。

修法三件套：
1. 循环启动前先 `delay(300)` 给相机绑定时间
2. 把 `Not bound to a valid Camera` / `Camera is closed` 识别为**可重试**错误，不当成真故障弹给用户
3. 抛可重试错误时唤醒循环稍后重试

## 验证

- logcat 连续输出 `captured` / `recognized`，且 `Not bound to a valid Camera` 计数为 **0**
- 自动模式下画面静止时出现 `frame unchanged, reuse cached result`

## 遗留

默认值后来按用户要求改成 **手动**（见任务 10）。
