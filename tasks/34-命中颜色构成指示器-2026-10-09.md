## 目标

> 需求原话：「在命中7/11 这里的右边加上 1 点 2 点 3 分别代表此次识别到了对应的几个」
>
> 追问后明确：「一个黄色的点（黄色）1 一个绿色的点（绿色）1，这样子」
>
> 顺序与范围：「黄 蓝 绿」、「只加取景页结果面板」

一句话：**在结果面板标题行的「命中 X / Y」右边，按颜色给出这次命中的构成**，
形如「颜色点 + 数字」一组一种颜色。

```
命中 10 / 34   ● 7   ● 3                        重拍
               ↑蓝    ↑绿
```

## 一、为什么是「点 + 数字」而不是「画 N 个点」

第一版理解成「有几个就画几个点」，提了两个选项让用户选。用户澄清是
**一个点跟一个数字**（`● 1`）。

这个形态反而更省地方：**宽度是固定的**（最多三组），不会因为命中 11 条就把
标题行撑爆——所以当初问的「点数要不要封顶」这个问题自然消失了，不用再管。

三组数字之和**正好等于** `命中` 那个数（未命中的行没有颜色，不进任何一组），
所以标题行本身自洽，可以互相验算。

## 二、顺序：黄 → 蓝 → 绿（和枚举顺序不一样）

★ 需求明确指定 **黄 → 蓝 → 绿**，而：

- `HitColor` 的枚举声明顺序是 **绿 → 黄 → 蓝**
- 「条件暂停」那排提示点（任务 32）用的是枚举顺序，也是 **绿 → 黄 → 蓝**

也就是说这里的顺序和项目里另外两处**都不一样**。看起来像手滑，但它是需求指定的，
所以专门抽了个常量并写了注释，免得以后有人「顺手修正」：

```kotlin
/** 「命中 X / Y」右边那几组的显示顺序：需求指定，不是枚举顺序 */
private val HIT_COUNT_ORDER = listOf(HitColor.Yellow, HitColor.Blue, HitColor.Green)
```

## 三、代码（`ResultPanel.kt`）

分类直接复用「条件暂停」用的那个判据，保证**和屏幕上的颜色一字不差**
（包括「已标记的精确命中算蓝不算绿」这条优先级）：

```kotlin
val colorCounts = matches.groupingBy { hitColorOf(it) }.eachCount()
```

★ key 里会有 `null`（未命中的行），下面按三种颜色取值时自然被忽略，不用特判。

渲染是个私有小 composable，`counts[kind]` 为 0 或不存在时整组不画：

```kotlin
@Composable
private fun HitColorCounts(counts: Map<HitColor?, Int>, modifier: Modifier = Modifier) {
    val ordered = HIT_COUNT_ORDER.mapNotNull { kind ->
        counts[kind]?.takeIf { it > 0 }?.let { kind to it }
    }
    if (ordered.isEmpty()) return
    ...
}
```

- 一组 = 圆点（`clip(CircleShape)` + `background(kind.color)`）+ `3dp` 间距 + 数字
- **数字和点同色**：一眼看出这一对是一体的，也对得上结果行里的颜色
- 组与组之间 `8dp`（`Arrangement.spacedBy`），否则三种颜色挨在一起读不出来
- 挂在 `/ ${matches.size}` 后面，`padding(start = 10.dp)`
- 插在「命中 X / Y」和「重拍」之间：`重拍` 左边本来就有个 `Spacer(weight(1f))`，
  所以它仍然贴最右，不受影响

> 后续调整：点的**半径**缩小一半（直径 6dp → 3dp），按用户要求。常量是直径
> `HIT_COUNT_DOT`，改的时候别只对半径算——`Modifier.size()` 收的是直径。

## 四、落地页同步（`pages/index.html`）

### 新增的指示器

- CSS 加 `.ph-cc`（色点 + 数字）、`.ph-cc.y/.b/.g` 三个色值。点用
  `background: currentColor`，颜色由所在 span 决定
  ★ 数字**不能**用 `<b>`：`.ph-panel .count b` 那条规则会把字号顶到 11px 并染成黄色
- 示意图那一行改成：

```html
<div class="count">命中 <b>4</b> / 11<span class="ph-cc y"><i></i>1</span>…</div>
```

- 正文补一段说明：顺序 黄→蓝→绿、三组数字之和等于 X、0 的整组不显示

### 顺手改掉的两处不一致

1. **示意图自己前后矛盾**：面板列了 4 条命中（蓝1+绿2+黄1），
   `count` 却写「命中 3 / 11」，顶部状态胶囊更写「命中 3 / 20」。
   而 App 里胶囊和面板说的是**同一帧**（`StatusBanner` 和 `ResultPanel` 用的是同一批
   matches）。改成两边都是「命中 4 / 11」，并把数字和列出的行对齐（4 = 1+2+1）。
2. **版本号过期**：`Recognizer304 v0.3.4` → `Recognizer305 v0.3.5-Hephaestus`
   （和真机底部显示的一致；上一版只在任务 32 同步过一次）
   - 顺带确认加长后**没有溢出**手机边框（截图核对过）

### `.ph-miss` 也补上不换行

`.ph-hit` 早就写着 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`，
但**未命中的行** `.ph-miss` 没有——App 里所有行都是单行，所以补上，让这条注释
在 CSS 里是完整成立的。
