## 目标

> 需求原话：「把识别结果的文本框上移一点，不要和那几个采样的选项重叠」
>
> 「让那几个选项不要横向拖动，缩小以下横向之间的间距，但是要总共铺满屏幕的width」

两条都是[任务 18](18-识别管线与相册节流-2026-10-07.md) 加「识别模式行」带出来的后遗症：
底部控件从**一行**变成**两行**，原来按一行算的死值就不对了，新加的选项行也放不下。

真机基准值（小米，`wm size` 1220×2712 / `wm density` 520 / 三键导航）：

- 1dp = 520/160 = **3.25px**
- 屏宽 1220px = **375.4dp**
- `WindowInsets.navigationBars` ≈ **48dp**

---

## 一、结果面板被模式行压住

面板还是按只有一行控件时的老办法定位的：

```kotlin
modifier = Modifier
    .align(Alignment.BottomCenter)
    .padding(bottom = 150.dp)   // ← 当初底部只有「缩略图/快门/模式开关」一行
```

底部控件栏自下而上的实际占用：

| 自屏幕底部 | 高度 | 累计到 |
|---|---|---|
| `navigationBars` | 48dp | 48dp |
| `padding(bottom = 18.dp)` | 18dp | 66dp |
| 快门行（`SHUTTER_SIZE` = 76dp，最高的那个） | 76dp | 142dp |
| 模式行（`titleSmall` 行高 20dp + 上下各 8dp + `padding(bottom = 8.dp)`） | 44dp | **186dp** |

也就是说**模式行占 142–186dp**（自屏幕底部算），而面板的底边被放在 **150dp**。
面板的 body 是从 150dp 往上长的，于是它盖住了模式行 150–186dp 这一段——**压进去 36dp**，
正是看到的「结果文本框和那几个采样的选项重叠」。

### 修法

没有把 150 改成 200 这种「再猜一个数」（下次再加一行控件照样错），
而是**让面板和控件栏共用一个 `Column`**：

```kotlin
Column(
    horizontalAlignment = Alignment.CenterHorizontally,
    modifier = Modifier
        .align(Alignment.BottomCenter)
        .fillMaxWidth()
        .windowInsetsPadding(WindowInsets.navigationBars)
        .padding(bottom = 18.dp)
) {
    if (displayMatches != null) {
        ResultPanel(
            ...,
            modifier = Modifier
                .padding(horizontal = 16.dp)
                .padding(bottom = 12.dp)   // 和模式行之间留的缝
        )
    }
    PipelineModeRow(...)
    Row { /* 缩略图 / 快门 / 模式开关 */ }
}
```

Column 的底边钉在屏幕底部，面板只会**往上长**。所以面板多高、模式行多高、
导航栏多高都不会互相压住，也不用再维护「面板要抬高多少 dp」这种跟着布局飘的常量——
出这个问题的根因就是那个常量。

面板底边从 150dp 变成 186 + 12 = **198dp**，正好上移 **48dp**。

## 二、模式行改成五等分

### 问题

原来这一行是「按内容宽度排 + 横向滚动」：

```kotlin
Row(
    horizontalArrangement = Arrangement.spacedBy(2.dp),
    modifier = Modifier.fillMaxWidth().horizontalScroll(rememberScrollState())
) {
    Spacer(Modifier.width(14.dp))
    Pipeline.entries.forEach { item ->
        Text(
            ...,
            modifier = Modifier.padding(horizontal = 14.dp, vertical = 8.dp)
        )
    }
    Spacer(Modifier.width(14.dp))
}
```

按 375.4dp 屏宽算这一行的内容宽度：

| | 宽 |
|---|---|
| 5 个标签（14sp，标准 2 字 / 省内存 3 / 降采样 3 / 小图直出 4 / 流式分析 4） | 28+42+42+56+56 = **224dp** |
| 每项左右各 14dp 内边距 × 5 | **140dp** |
| 4 条 2dp 间隔 | **8dp** |
| 首尾各 14dp 撑边 | **28dp** |
| **合计** | **400dp** |

400dp > 375.4dp，**溢出 24.6dp**，所以必须横拖，最右边那项还会被切掉一截——
一眼看不全有哪些模式。

### 修法

去掉滚动，改成 `weight(1f)` 等分：

```kotlin
Row(
    verticalAlignment = Alignment.CenterVertically,
    horizontalArrangement = Arrangement.spacedBy(4.dp),   // 只留一条缝，点击态不贴一起
    modifier = modifier.fillMaxWidth().padding(bottom = 8.dp)
) {
    // 用 for 而不是 entries.forEach：forEach 的 lambda 收不到 RowScope，
    // 里面的 Modifier.weight(1f) 会解析不到
    for (item in Pipeline.entries) {
        Text(
            text = item.label,
            textAlign = TextAlign.Center,
            ...,
            maxLines = 1,
            modifier = Modifier
                .weight(1f)
                .clip(RoundedCornerShape(50))
                .clickable { onSelect(item) }
                .padding(vertical = 8.dp)          // 横向内边距交给 weight 分配，这里不写
        )
    }
}
```

| | 旧 | 新 |
|---|---|---|
| 排布方式 | 内容宽度 + 横向滚动 | **五等分**（`weight(1f)`） |
| 每项槽宽 | 44–84dp 不等 | **71.9dp** 全部相同 |
| 相邻间隔 | 30dp（14+14 内边距 + 2 间隔） | **4dp** + 文字居中留下的空白 |
| 内容总宽 | 400dp（溢出 24.6dp） | **恰好 375.4dp** |
| 最长标签（56dp）余量 | — | 每侧 **约 8dp** |

> 用 `weight` 而不是让内容撑开：无论标签多长、系统字号多大，
> 这一排都恰好铺满、**永不溢出**，所以「不要横拖」是由结构保证的，不是靠调数值凑出来的。

顺带删掉了两个只为撑边存在的 `Spacer`，以及不再使用的
`horizontalScroll` / `layout.width` 两个 import。

## 备注

`for (item in Pipeline.entries)` 这个写法不是风格问题：Compose 的 `Modifier.weight(1f)`
是 `RowScope` 的扩展，而 `Pipeline.entries.forEach { }` 的 lambda 接收者是 `Pipeline`
（`forEach` 不会传递外层 receiver），在里面写 `weight` 会解析不到、编译不过。
`for` 循环不改变 receiver，所以能直接用。
