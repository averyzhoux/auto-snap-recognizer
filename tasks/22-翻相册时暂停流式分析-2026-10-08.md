## 问题

任务 18 做流式分析时就发现了、记在「已知遗留」里没修：

> 自动模式那边有 `if (screen != Screen.Camera) return@LaunchedEffect` 这道闸，
> 但 `ImageAnalysis` 没有。

具体后果：**翻内部相册 / 看数据集时，相机还在推帧、还在跑 ML Kit、还在往相册里塞新照片**
（被 3 秒节流限着，但确实在塞）。

根因是这两个页面都是**同一个 Activity 里的 Compose 覆盖层**，不会触发 `onStop`，
`ProcessCameraProvider` 绑的是 Activity 生命周期，所以 CameraX 根本不知道你已经翻页了。

`ImageCapture` 那四条管线不受影响：

- 自动模式：`LaunchedEffect(..., screen, ...)` 把 `screen` 当 key，翻页就把循环取消了
- 手动模式：覆盖层盖住了快门，点不到

所以只有流式分析的 `ImageAnalysis.Analyzer` 需要补这道闸。

## 改法

给 `CameraPreview` 加一个 `deliverFrames: Boolean`，由调用方传 `screen == Screen.Camera`：

```kotlin
if (currentDeliverFrames) {
    onFrame(image)
} else {
    image.close()   // 必须关，否则相机管线会卡住
}
```

### ★ 坑：参数不能直接读，要走 `rememberUpdatedState`

```kotlin
val currentDeliverFrames by rememberUpdatedState(deliverFrames)
```

`analyzer` 是被 `DisposableEffect(lifecycleOwner, pipeline)` 捕获的，
**key 里没有 `screen`**，所以翻页时它不会重建。直接读 `deliverFrames` 参数，
读到的是「建 analyzer 那一刻」的布尔值——一直是 `true`，闸门等于没加。

`rememberUpdatedState` 是 Compose 里「把一个会变的参数安全地喂给长期存活的 effect」的标准做法。
这和任务 18 里 `derivedStateOf` 那个坑是同一类问题（lambda 捕获的是值还是委托），
只是表现相反：那边要用委托才能活读，这边要用 `rememberUpdatedState`。

### 为什么不用另一种方案

讨论时提过另一条路：`LaunchedEffect(screen)` 控制 `clearAnalyzer()` / 重新 `setAnalyzer`。
没选它，因为重新绑定相机会有约 300ms 的空白闪烁，而这里要的效果只是「别再处理了」，
丢帧就够了——帧本身还在相机内部转，不额外占我们的 CPU。
