# 08 · 内部相册（纵览页）

## 目标

> 需求原话：「做个内部的相册，点击左下角的缩略图可以进入"相册"，每个相片只保留缩略图，和对应的识别结果」

## 做了什么

- 新增 `GalleryItem`：缩略图 + 序号 + 时间戳 + 命中数/总行数 + 识别文字 + 完整比对结果
- 三级屏幕状态：`enum class Screen { Camera, Gallery, Detail }`（原来的布尔量不够用了）
- 点左下角缩略图进相册；相册为**两列网格**，最新的排最前
- 每格显示：缩略图 + `#编号` + 时间 + `命中 X / Y`（命中时变黄）+ 前 3 行识别文字
- 「清空」按钮
- 相册打开时**暂停自动拍摄**（`LaunchedEffect` 的 key 加上 `screen`）

## 关键决策

- **只存缩略图 + 识别结果，不存 12MB 原图**。这是用户明确要求的，也顺便解决了内存问题。
- 相册里的缩略图存的是**独立拷贝**，不和状态栏共享同一个 Bitmap——避免「一边回收、另一边还在画」的崩溃。代价是每张多一份内存。

## 踩坑

- **`LruCache` 的 `entryRemoved` 里 `recycle()` 位图是危险的**：被挤出缓存的位图可能还被某个正在合成（或 LazyGrid 预取）的卡片持有，回收后再绘制会抛 `trying to use a recycled bitmap`。改成交给 GC——代价是快速滚动时短暂多占几 MB，换来不崩。
- 结果面板又长又挡画面，后面单独做了分界线与排序（任务 11）。

## 验证

截图确认：网格布局、缩略图、编号时间、命中数、识别文字摘要都正确。

## 遗留

此时相册是**纯内存**的，APP 一关就清空。落盘在任务 10 做。
