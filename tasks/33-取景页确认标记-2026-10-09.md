## 目标

> 需求原话：「需要在识别后的显示区域给每个结果加一个按钮，用来便捷确认是否被标记。
> 相册内和取景页都要做。给人一个可选择的按钮，此标记就是数据集中的标记」
>
> 中途收敛：「那就不改变相册了，只把取景页面的那个显示做这个功能」
>
> 「只在手动模式和自动模式暂停时才有这个功能。把按钮放在最右侧即可」
>
> 「每个模式的条件暂停触发和手动模式」
>
> 「相册就是快照，不需要改动。但是可以把相册改名为快照」
>
> 「只改 相册200张 为 快照200张这里即可」
>
> 「按钮是每行行尾各一个」

一句话：**在取景页结果面板里，每一行命中结果的行尾放一个可点的小方框，
点一下就把这一项标记成「已识别」（再点一下取消），也就是数据集里那个标记本身。**

## 一、按钮改的是数据集里那一项，不是这一帧的临时状态

`matchColor()` 的蓝色判据是 `match.entry?.marked`，而 `entry` 只能来自数据集
（`OcrMatcher` 的候选就是从数据集的 `Entry` 建的）。所以取景页这个按钮**只能是**
数据集标记的另一个入口——没有「只对这一帧有效」的实现方式，除非给 `LineMatch`
另加一个与 `Entry.marked` 无关的字段，那它就不落盘、不进三色体系了。

结论：**按钮 = 数据集编辑页 `MarkBox` 的同一个开关。**
点一下会落盘，下次扫到、重开 App 之后都还在。

## 二、显示判据：`activelyCapturing`，不是 `continuousCapture`

需求是「手动模式 + 每个模式的条件暂停」。这两个在代码里不是同一个布尔值：

| 管线 | 条件暂停触发时做什么 | `continuousCapture` |
|---|---|---|
| 基础 / 省内存 / 降采样 / 小型图 | `autoMode = false` | `false` |
| **流式** | `analysisPaused = true` | **恒 `true`** |

★ `continuousCapture = pipeline.usesAnalysis || autoMode` 对流式**恒为 true**，
所以拿它当判据，流式被条件暂停停住之后按钮永远出不来。

新增一个判据（`MainActivity.kt`）：

```kotlin
val activelyCapturing by remember {
    derivedStateOf { if (pipeline.usesAnalysis) !analysisPaused else autoMode }
}
```

| 状态 | `activelyCapturing` | 按钮 |
|---|---|---|
| 四条非流式管线的手动模式 | false | 显示 |
| 四条非流式管线被条件暂停（`autoMode` 被置回 false） | false | 显示 |
| 流式被条件暂停 | false | 显示 |
| 流式被**用户自己**按「暂停」 | false | 显示 |
| 自动 / 流式正在跑 | true | 不显示 |

**正在跑必须藏起来**，不只是需求这么要求：结果每秒被新帧整体替换，手指刚瞄好的
行会跳走。

> 已知取舍：判据**区分不出**「条件暂停停的」和「用户自己按暂停停的」。要区分只能用
> `pausedByHit`，代价变成「自己暂停后反而不能标记」，更别扭。所以只要没在抓帧就能标。

## 三、代码

### 1. `MarkToggle`：抽出一份可点的标记框（`DatasetScreen.kt`）

原来的 `MarkBox` 只画不可点，改成：

```kotlin
internal fun MarkToggle(marked: Boolean, onClick: (() -> Unit)? = null,
                        size: Dp = 22.dp, touchSize: Dp = 26.dp)
```

- `onClick == null` → 只显示，**外层 Box 就是 `size`**，和原来的 `MarkBox` 逐像素一致
  （编辑页那一行整行可点，框自己不接点击，避免嵌套点击区互抢事件）
- `onClick != null` → 外面套一圈 `touchSize` 的透明触摸区
- 图形部分抽成私有的 `MarkSquare`，两处共用同一份画法

★ 触摸区靠 `contentAlignment = Center` 让方块保持**正中**，不用 padding 去凑——
触摸区比图形大多少，视觉重心就被压低多少（任务 32 记过这个坑）。

### 2. 行尾按钮（`ResultPanel.kt`）

```kotlin
internal fun ResultPanel(..., onRetake: () -> Unit,
                         onToggleMark: ((Entry) -> Unit)? = null, modifier: Modifier = Modifier)
internal fun MatchRow(match: LineMatch, onToggleMark: ((Entry) -> Unit)? = null)
```

★ **默认值必须是 `null`**：相册详情页的两个 `MatchRow(match)` 调用点一个字都不用改，
按钮天然不会出现在相册里。这是「相册不动」这条约束最省事的落地方式——
不是靠判断屏幕，而是靠相册调用方压根不传这个参数。

行布局上包了一层 `weight(1f)` 的 Row：

```kotlin
Row(verticalAlignment = CenterVertically) {
    Text(if (hit) "✓" else "·")
    Row(horizontalArrangement = spacedBy(8.dp), modifier = Modifier.weight(1f)) {
        Text(rawText, weight(1f, fill = false))
        if (hit) Text("→ ${entry.name}${note}", weight(1f, fill = false))
    }
    if (entry != null && onToggleMark != null) MarkToggle(...)   // 行尾
}
```

★ 为什么要多包一层：两段文字都是 `weight(fill = false)`，**剩多少才占多少**。
不套这一层，按钮会紧跟在文字屁股后面，每行的横向位置都不一样；套上之后
内层 Row 吃掉全部剩余宽度，按钮才被顶到行尾、各行对齐。

`MarkToggle(size = 20.dp, touchSize = 26.dp)`：触摸区 26dp 比行内文字（约 20dp）高，
所以**命中行会高约 6dp**（未命中行没有按钮、高度不变）。代价是面板同样高度下
少看约半行，换来的是手指能点中。这个值可以调，调小就更难点。

### 3. `toggleEntryMark`（`MainActivity.kt`）

和数据集编辑页的 `toggleMark` 是同一个动作的另一个入口——**四步一个都不能少**：

```kotlin
activeEntries = updated                 // 内存镜像
matcherHolder.value = OcrMatcher(updated)  // ① 引擎里的 Entry 是旧实例
lastSignature = null; lastMatches = null   // ② 帧缓存会直接复用旧 matches
status = status.withEntryMarks(updated)    // ③ 就地刷新当前显示的那一份
scope.launch { datasetStore.saveEntries(meta.id, updated) }  // ④ 立刻落盘
```

★ 第 ③ 步是取景页**比编辑页多出来的**：编辑页改完退出就是新数据，而取景页手动模式下
**本来就没有下一帧**，不刷的话点了按钮要等到重拍才变色，看起来像没反应。

★ 新增 `activeEntries`（内存镜像）：`OcrMatcher` 只进不出，拿不回条目列表。
**所有重建 matcher 的地方都要同步更新它**（启动加载 / 切数据集 / 编辑页改标记），
否则会把标记写回一份过期的条目。

### 4. 两个纯逻辑函数（为了能单测）

| 函数 | 位置 | 作用 |
|---|---|---|
| `toggleEntryMarked(entries, name): List<Entry>?` | `DatasetStore.kt` | 按**名字**翻转标记；名字对不上返回 `null` |
| `remapEntryMarks(matches, entries): List<LineMatch>` | `CapturePipeline.kt` | 把结果里的 `Entry` 换成新实例 |
| `OcrStatus.withEntryMarks(entries)` | `CapturePipeline.kt` | 上面那个的状态版（识别中的缓存也刷） |

★ **按名字对齐，不能比引用**：结果里的 `Entry` 是匹配那一刻从旧 matcher 带出来的实例，
和刚读出来的这份列表不是同一批对象。名字对不上时必须**什么都不做**——
「猜一个最近的」会静默改错项，而且不报错。

抽成顶层函数而不是私有方法，理由和 `parseMatchKind` 一样：这些逻辑出错**只会静默
不变色 / 静默改错项**，没有异常也没有日志，必须靠单测兜。

### 5. 「相册」→「快照」（`GalleryScreen.kt`，只改一个字符串）

```kotlin
text = "快照 ${items.size} 张"
```

只改纵览页顶栏这一处。**详情页的返回按钮仍写「相册」，代码标识符（`GalleryStore` /
`GalleryItem` / `MAX_GALLERY_ITEMS`）和注释里的「相册」全部不动**——类名保持一致，
也免得 `git log` 里的历史文件名断掉。

改名要传达的是：这里是**拍摄当时**的记录，不会跟着数据集后来的标记变化
（`GalleryStore` 里 `marked` 是按快照存的）。

## 四、明确不做的

- **相册不加按钮、不改 JSON、不改颜色逻辑**：照片里的 `marked` 仍是拍摄当时的快照。
  所以取景页刚标成蓝的项，进相册看那张照片**还是绿/黄**——这是刻意保留的语义。
- **未命中行没有按钮**：`entry == null`，没有可标记的对象。
- **点标记不会让行重排**：`marked` 不参与匹配，`sortedByDescending { isHit }` 不变。
- **取消标记后看不出「曾经标过」**：开关语义的必然结果。
