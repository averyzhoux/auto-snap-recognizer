## 目标

> 需求原话：「切换到流式模式后，默认是暂停状态，然后切换后显示一个上拉图案，
> 二次点击流式按钮后，展开一个设置页面，调节各项设置。比如间隔，还有其他可选设置你可自己加。」

三件事：

1. 切到「流式」→ **默认暂停**，不自动开跑
2. 选中的「流式」标签上显示一个**上拉图案**（提示这里能拉出东西）
3. **再点一次**这个标签 → 从底部展开设置面板

## 一、默认暂停

```kotlin
// 切管线时
analysisPaused = picked.usesAnalysis     // 进流式 = true（暂停），换别的 = false
```

`deliverFrames = screen == Screen.Camera && !analysisPaused`，所以暂停时 analyzer 直接
丢帧、`image.close()`，相机不再往识别那边喂东西。右下角的圆钮显示「继续」。

先暂停再让人点「继续」，作用是**留出调设置的时间**——不然一切过去就开始跑，
改间隔得先暂停一次，很别扭。

## 二、上拉图案

选中的「流式」标签渲染成 `流式⌃`：

```kotlin
text = if (selected && item.usesAnalysis) "${item.label}⌃" else item.label
```

只加在**选中**的时候——没选中时它只是个可切换的普通标签，挂个箭头会让人以为
那一项本身有下拉。

## 三、二次点击展开设置

模式行的回调现在区分「第一次点」和「再点一次」：

```kotlin
onSelect = { picked ->
    if (picked == pipeline) {
        if (picked.usesAnalysis) settingsOpen = true   // ★ 再点一次 = 拉出设置
    } else {
        pipeline = picked
        analysisPaused = picked.usesAnalysis
        settingsOpen = false
    }
}
```

面板从底部动画上滑（`AnimatedVisibility` + `slideInVertically`），后面压一层
半透明遮罩，点遮罩任意处收起。

## 四、设置项

`StreamSettings`（只存内存，切管线/重启回默认）：

| 设置 | 选项 | 默认 | 真的生效在哪 |
|---|---|---|---|
| **分析间隔** | 4 个预设标签 **+ 右侧一个自填毫秒数的输入框** | 不限 | `processFrame` 开头限速：距上次处理不足间隔就丢帧 |
| **相册保存间隔** | 1 / 2 / 3 / 5 秒 | 3 秒 | `shouldSaveToGallery` 的时间闸门 |
| **只保存有命中的帧** | 开 / 关 | 关 | `shouldSaveToGallery` 额外要求 `hitCount > 0` |

三项都是**真接线**的，不是摆设开关。

### 分析间隔的自填输入框

预设标签**保留**，输入框是**并联**的第二种填法，不是替代：

```
分析间隔 [自填] 毫秒
两帧之间至少等这么久。也可以直接在右边填毫秒数；不限 = 来一帧处理一帧
[不限] [0.2 秒] [0.5 秒] [1 秒]
```

输入框**紧挨着「分析间隔」四个字**，不是推到屏幕右边——后者离标题太远，
一眼看不出它属于哪一项（`Spacer(weight(1f))` 会把它顶到最右）。

- 点预设标签 → 输入框跟着填上那个值
- 自己打字 → 值不在预设里，**所有标签都不再高亮**（表示这是自定义值）
- 清空输入框 = `0` = 不限速（所以 `0` 显示成空，而不是显示一个「0」）
- 只收数字、最多 5 位（99999ms ≈ 100 秒），避免输入出奇怪的东西

用 `BasicTextField` 而不是 `OutlinedTextField`：后者的最小高度是 56dp，
塞在标题行右边会把整行撑高，和面板其它地方不协调。自绘一个 30dp 高的圆角底，
空的时候显示「自填」占位。


### 分析间隔为什么放在 `toBitmap()` 之前

```kotlin
if (pipeline.usesAnalysis && streamSettings.analysisIntervalMs > 0) {
    val now = SystemClock.elapsedRealtime()
    if (now - lastAnalysisAt.get() < streamSettings.analysisIntervalMs) {
        image.close()        // ★ 必须关，否则相机管线卡住
        return@frame
    }
    lastAnalysisAt.set(now)
}
```

YUV→RGB 转换（`toBitmap()`）是这条路上最贵的一步。放在它**之前**丢帧，
限速才真的省 CPU 和省电；转完再扔等于白干。

顺带：`相册保存间隔` 原来的常量 `GALLERY_SAVE_INTERVAL_MS` 保留成 `StreamSettings`
的**默认值**来源，所以没动过设置时行为和以前完全一样。

## 五、面板长什么样

```
        ▁▁▁                              ← 抓手（示意可下拉）
  流式设置                        关闭
  分析间隔
  两帧之间至少等这么久。调到最大能省电，识别会跟着变慢
  [不限] [0.2 秒] [0.5 秒] [1 秒]
  相册保存间隔
  连续推帧时最多隔这么久存一张，免得相册几秒钟就写满
```

## 六、后面追加的改动

### 6.1 「重拍」从单独一行挪到标题行右侧

原来它在面板**最底部单占一行**，只有两个小字却吃掉一整行高度。挪到「命中 X / Y」
那一行的最右侧（`Spacer(weight(1f))` 推过去），点击区内边距从 `16dp / 6dp` 收到 `12dp / 2dp`。
`continuous`（自动 / 流式）时仍然不显示。

### 6.2 分析间隔加自填输入框

预设标签**保留**，标题右侧加一个自填毫秒数的输入框，两者**并联**：

- 点预设标签 → 输入框跟着填上那个值
- 自己打字 → 值不在预设里，所有标签都不再高亮（表示这是自定义值）
- 清空 = `0` = 不限速（所以 `0` 显示成空，不是一个「0」）

> ★ 踩过一个坑：`SettingSection` 的 `trailing` 容器一开始是 `Box`，改成
> 「输入框 + 单位」两个 composable 之后，**Box 把它们叠在了一起**，单位文字压到输入框上。
> 容器必须是 `Row`。这个错编译不报、测试也测不到，只能靠肉眼看。

### 6.3 泛化成「管线设置面板」

降采样也要有设置，于是把面板按管线分节。**两条管线的项不共用**：

| 管线 | 设置项 |
|---|---|
| 流式 | 分析间隔 / 相册保存间隔 / 只保存有命中的帧 |
| 降采样 | 长边像素 / 分析间隔（自动模式抓帧周期） |

> 一开始把「相册保存间隔 / 只保存有命中的帧」做成两条管线共用的，后来去掉了：
> 那两项是给**连续推帧**用的；降采样是快门一帧一帧，每次按快门本来就该留一张，
> 「保存间隔」无从谈起，而「只存命中」还会把手动拍的没命中的照片吃掉。

- 文件 `StreamSettingsSheet.kt` → `PipelineSettingsSheet.kt`，
  `StreamSettings` → `PipelineSettings`（多 `downscaleLongEdge` / `captureIntervalMs`）
- `Pipeline.configurable`（= 流式 or 降采样）决定「选中时标签上方有没有上拉箭头」、
  「再点一次会不会展开面板」
- 面板标题跟着管线走：`${pipeline.label}设置`

> ★ **两个「分析间隔」是两个字段，故意没有合并**：
> - 流式的 `analysisIntervalMs`：画面来得太快就把多余的丢掉，`0` = **不限速**
> - 降采样的 `captureIntervalMs`：没人按快门时多久自己抓一次，`0` = **用默认的 1 秒**
>
> 一个 0 表示「不限制」、另一个 0 表示「用默认」，语义相反。共用一个字段迟早出错。
> 降采样那个读的是自动抓帧循环的 `delay`：
> `delay(if (interval > 0) interval else AUTO_CAPTURE_INTERVAL_MS)`——
> 真按 0 跑就是死循环式连拍。

### 6.4 降采样的长边：只填一个数，其余自动算

> 需求原话：「降采样只需要设置长边像素，并且自动计算短边像素和图片大小，图片比例等信息。」

面板上多一行实时算出来的信息：

```
长边像素 [2560] px
喂给识别前先把图缩到这个尺寸。越小越快、越省内存，但远处的小字可能认不出
[1280] [1600] [2048] [2560]
短边 1920 px · 4.9 MP · 比例 3 : 4      ← 自动算的
```

- **短边** = 长边 × 比例
- **MP** = 长边 × 短边 ÷ 10⁶（保留一位小数）
- **比例** = 长短边约分（`gcd`），`1536 : 2048` → `3 : 4`

**比例从哪来**：不让使用者填第二遍。比例是设备和传感器的属性，直接从相机的输出规格读：

```kotlin
imageCapture?.resolutionInfo?.resolution   // 绑好相机后才有
```

★ 绑好之前 `resolutionInfo` 是 `null`，这时按 `3/4`（4:3 竖屏）估一个。
估错也只是面板上那行提示数字不准，**不影响实际缩放**。

实机验证（截图）：长边选 2560 → 显示 `短边 1920 px · 4.9 MP · 比例 3 : 4`，
和 2560×0.75=1920、2560×1920=4.9MP、gcd(2560,1920)=640→3:4 完全对得上。

### 6.5 5 条管线都有面板 + 模式说明 + 间隔排第一

- **`Pipeline` 加 `description`**：一条管线一句话，进面板先看到它，再往下才是能调什么。
  写在枚举里而不是面板里，是因为它描述的就是这条管线本身
- **间隔提到第一个设置**，5 条管线都有：
  - 流式 → **分析间隔**（`analysisIntervalMs`，丢帧限速）
  - 基础 / 省内存 / 降采样 / 小型图 → **抓帧间隔**（`captureIntervalMs`，自动抓帧周期）
- 两个名字**故意不同**：一个调「丢不丢」，一个调「多久抓一次」，同名会让人以为在调同一件事
- `Pipeline.configurable` 随之删掉——所有管线都可配置了，判据退化成「是否选中」

面板结构：

```
<Pipeline>设置                                  关闭
<一句话说明这条管线是干什么的>

间隔（分析间隔 / 抓帧间隔）   [自填] 毫秒
[预设标签…]

<管线自己的设置>
  流式   → 相册保存间隔 / 只保存有命中的帧
  降采样 → 长边像素（+ 自动算出的短边/像素/比例）
  其余   → （没有）
```
