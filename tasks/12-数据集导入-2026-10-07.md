## 目标

把硬编码的示例表格换成可导入、可保存、可切换的数据集。

> 需求原话：「接下来，开始导入数据，并且保存每次导入的数据用以复用。按钮放在哪里以什么样子形式合适，先讨论」

## 先讨论，后动手

按「先讨论」的要求先给了三个选项，用户选择：

| 问题 | 选择 |
|------|------|
| 表格结构 | **单列关键词**（一行一个词） |
| 数据来源 | **文件选择器 + 粘贴文本**，两者都要 |
| 入口位置 | **顶部右侧「数据集」胶囊** |

关于入口位置的判断依据：**「当前用的是哪个表格」必须一眼可见**——否则识别结果不对时，你会以为是识别错了，其实是表格没切。这不只是入口，是功能性需求。

## 做了什么

- `DatasetParser.kt` —— 解析 + 编码探测。**纯函数、不碰 Context**，所以能在电脑上跑单测
- `DatasetStore.kt` —— 落盘 / 列表 / 删除 / 激活：
  ```
  filesDir/datasets/
      index.json          全部数据集的元信息 + 当前激活的是哪个
      <id>.csv            导入时的原始文件副本
      <id>.entries.json   解析后的条目，匹配引擎直接读
  ```
- `DatasetParserTest.kt` —— 16 个单测
- UI：顶部右侧胶囊 + 数据集管理页 + 导入预览确认页 + 粘贴对话框
- 导入流程：选文件/粘贴 → **预览确认** → 命名 → 保存并切换

## 解析规则（容错，不因一行有问题就整体失败）

- 跳过空行、`#` 注释行
- 一行一个条目；用逗号 / 制表符 / 分号分隔时，**第一个是名称，其余当别名**
- 去掉两侧空白和 CSV 引号
- 名称重复的合并别名，不产生重复条目

## 编码探测

Excel 在中文 Windows 上导出的 CSV 默认是 **GBK**，按 UTF-8 读会全是乱码。所以按顺序试探：

```
UTF-8 BOM  →  严格 UTF-8（非法字节就抛）  →  GBK
```

导入预览页会显示识别到的编码，一眼能确认。

## 踩坑

**切换数据集后，正在跑的自动拍摄循环仍在用旧表格。**

原因：`matcher` 原来是个普通 `val`，被自动循环的 `LaunchedEffect` 在启动时捕获了。换成数据集后，那个循环手里的还是旧实例，要等循环重启才生效。

修法：把匹配引擎放进一个 holder（`mutableStateOf(OcrMatcher(...))`），回调里每次读 `.value`，切换立刻生效。

另一个坑：预览确认页**不能省**。用户当时导入了一个 `balance-2.html`，解析出 284 项——全是 HTML 标签。预览页是唯一能当场看出格式不对的地方。

## 验证

- 存储链路：直接往私有目录塞一个数据集，重启后日志 `dataset loaded: '测试表格' 3 entries`
- UI 四条路径（用户实测通过）：选文件、预览显示、导入后胶囊更新、内置数据集不可删
- 磁盘确认：原始副本 `model1\nmodel2` 与解析结果 `[{"name":"model1"},{"name":"model2"}]` 都在
