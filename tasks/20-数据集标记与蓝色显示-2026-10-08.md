## 目标

> 需求原话：「在数据集中在删除左侧加一个编辑按钮，点击后可以编辑数据集内容，点进去后，在每个数据的左侧加一个单选按钮，类似于 [-]，
> 用于让用户手动标记是否标记为识别过，对于这种标记后的数据，在识别显示的时候，采用蓝色。」

用途是扫货时当台账：核对过一条就在编辑页勾一条，下次再扫到它会显示成蓝色，
一眼看出「这条处理过了」，而不用靠脑子记。

---

## 一、数据模型

`Entry` 加一个字段（`OcrMatcher.kt`）：

```kotlin
data class Entry(
    val name: String,
    val aliases: List<String> = emptyList(),
    /**
     * 用户手动标记的「已识别过」。
     *
     * 这是**纯人工**的状态，比对引擎完全不看它、匹配逻辑一行都不受影响。
     * 它只影响命中之后**显示成什么颜色**。
     */
    val marked: Boolean = false
)
```

**关键取舍：`marked` 不进匹配逻辑。** 它不参与打分、不参与过滤，只在命中之后决定画成什么颜色。
这样「标记」这个功能出任何问题都不会影响识别本身——最多是颜色不对，不会漏命中或多命中。

## 二、持久化

### entries.json

数据集文件里多一个字段：

```json
[{"name":"TH-6983","aliases":[],"marked":true}]
```

读写都走 `DatasetStore` 新抽出来的 `encodeEntries()`（导入和编辑页共用，保证两边格式一致）。

★ **兼容旧文件**：读的时候是 `obj.optBoolean("marked", false)`。
升级前导入的表格里没有这个字段，`optBoolean` 读不到会回落到 `false`，
老数据自动视作「没标记过」，不会读崩。

### 新增 `DatasetStore.saveEntries(id, entries)`

- 只动 `<id>.entries.json`，**不碰 `<id>.csv`**——原始副本永远保留导入时的样子
  （这是 AGENTS.md 的硬约束：以后解析规则升级还能重新解析）
- 内置数据集直接返回 false（它的条目写死在代码里，改不了）
- `@Synchronized`：编辑页每点一下就写一次整份 JSON。人手点击最快百来毫秒一次，
  而内部存储写几十 KB 只要 1ms 左右，实际不会重叠；加锁是防「万一重叠时两个线程交错
  写出半个文件」——半个 JSON 会让整个数据集读不出来

### 相册 JSON

`GalleryStore` 的每行匹配结果也一并存 `marked`：

```kotlin
match.entry?.let {
    put("entry", it.name)
    put("marked", it.marked)   // 回看旧照片时颜色要和拍摄当时一致
}
```

读的时候同样 `optBoolean("marked", false)` 兼容旧照片。
这样**旧照片不会因为后来改了标记而变色**——照片记录的是拍摄那一刻的状态。

## 三、颜色优先级

```kotlin
private val MatchBlue = Color(0xFF4FC3F7)

private fun matchColor(match: LineMatch): Color? = when {
    !match.isHit -> null
    match.entry?.marked == true -> MatchBlue   // 人工标记压过自动判定
    match.isExact -> MatchGreen
    else -> XiaomiYellow
}
```

| 颜色 | 含义 |
|------|------|
| 蓝 | 手动标记过「已识别」（优先级最高） |
| 绿 | 完全相同 |
| 黄 | 近似 |
| 灰 | 未命中 |

选 `0xFF4FC3F7`：和绿色一样在深色面板上读得清，但色相离得远，不会和精确/近似混掉。

**蓝色自动覆盖三处显示**，因为它们都走 `matchColor()`：
拍摄页结果面板（`MatchRow`）、相册详情页（也用 `MatchRow`）、相册网格卡片（`CardLine`）。

## 四、UI

### 数据集列表：删除左边加「编辑」

抽了个 `RowAction` 复用样式，顺序是 **编辑**（黄）→ **删除**（灰）：

```kotlin
if (!meta.builtIn) {
    RowAction(text = "编辑", color = XiaomiYellow, onClick = onEdit)
    RowAction(text = "删除", color = Color.White.copy(alpha = 0.55f), onClick = onDelete)
}
```

内置示例数据集**没有编辑按钮**，和「不允许删除」保持一致——它的条目在代码里，改了没地方存。
（真实在用的数据集都是导入的，不受影响。）

### 编辑页 `DatasetEditScreen`

- 顶栏：`‹ 返回` + 数据集名 + 右侧实时「已标记 n」计数
- 列表每行：左侧标记框 + 名称 + 别名
- **整行都能点**，不用瞄准那个 22dp 的小方框

标记框 `MarkBox` 是自绘的小方块：未标记是空心框，标记后填蓝并打勾
（对应需求里说的 `[ ]` / `[✓]`）。刻意不用 Material 的 `Checkbox`——
一排几十个 Checkbox 视觉太重，而且这里的用法是「扫一眼看到哪些勾了」，
自绘小方框更好扫。

> 需求写的是「单选按钮」，实际按**每项独立的开关**做的（checkbox 语义）：
> 每一行是否标记是彼此无关的，radio 的「一组里选一个」语义在这里不成立。

### 编辑正在使用的那份表格

★ 这一步不能省，否则蓝色出不来：

```kotlin
if (meta.id == activeDataset?.id) {
    // 1) 匹配引擎里的 Entry 是旧实例（marked 还是老值），必须整个换掉
    matcherHolder.value = OcrMatcher(updated)
    // 2) 帧缓存会让当前画面直接复用旧结果，必须清掉才会重新跑一遍
    lastSignature = null
    lastMatches = null
}
```

两处都是坑：匹配引擎持有的是旧 `Entry` 实例；而 32×32 像素指纹命中时会跳过 ML Kit
并**直接复用上次的 matches**，不清缓存的话，画面不动就一直显示旧颜色。
