## 第一部分：装机复测发现的两个问题

改完包名后重新装机，发现：

### 问题 1：取景画面全黑

但拍照和识别都成功（缩略图有图、识别出 23 行），说明相机在工作。

排查：日志里两次启动的 `callingPackage` 分别是 `com.android.shell`（我用 adb 启的）和 `com.miui.home`（用户点了桌面图标）——**产生了两个 Activity 实例**，抢相机导致前景那个的 `PreviewView` 没画面。

修法：`android:launchMode="singleTop"`。已经在顶层时再点图标只走 `onNewIntent`，不再创建第二个实例。对相机应用这是必须的（否则重复绑定相机、重复初始化 ML Kit）。

### 问题 2：顶部两个胶囊重叠

状态文字长（`识别到 23 行，但都没命中表格`）时会横向撞上右侧的数据集胶囊，「识别」两字被压住。

修法分两步：
1. 把最长的状态文字缩成 `无命中 · 23 行`
2. 状态胶囊里的 `Text` 加 `maxLines = 1, overflow = Ellipsis`

## 第二部分：顶部栏布局又调了三轮

| 轮次 | 用户要求 | 实现 |
|------|----------|------|
| 1 | 数据集在右上、命中情况在左上 | `Row`：状态胶囊 `weight(1f)` + 数据集胶囊 |
| 2 | 状态胶囊在区域内**居中**，宽度随文字 | `Box(weight(1f), contentAlignment = Center)` 包住胶囊 |
| 3 | 还是**靠左**，但宽度仍随文字 | 同上改成 `CenterStart` |

最终实现的关键是**让谁让位**：`Row` 先量非加权子项（数据集胶囊拿到它需要的全部宽度），状态胶囊拿剩下的空间并在其中靠左。所以空间不够时是**状态文字先省略**，数据集永远完整可见。

## 第三部分：OCR 失败被误报成「没识别到文字」

> 需求原话：「OCR 失败被显示成『没到文字』，改为 [OCR 识别失败]」

原来 `recognize()` 的失败回调返回的是 `onResult(emptyList(), emptyList())`——和「识别成功但图里没字」**完全无法区分**。

### 改了什么

- `OcrStatus.Recognized` 加 `ocrFailed: Boolean` 字段
- `recognize()` 回调签名加 `ocrFailed` 参数，失败回调传 `true`
- 状态文案新增分支 `OCR 识别失败`（放在其它分支之前）
- 结果面板同步改成 `OCR 识别失败，请重试`，不再说「没有识别到文字，试试靠近一点」

### 顺带修掉一个隐藏的严重问题

失败回调原来会写帧缓存：

```kotlin
lastSignature = signature    // 记住"这一帧已处理过"
lastMatches = result         // 记下一份空结果
```

后果：自动模式下**画面不变就永远复用这份空结果，再也不会重试 OCR**——一次偶发失败会让那一幕永久卡在「没文字」。

现在失败时**不写**这两个值，下一帧会重新识别。

## 验证

这个文案平时**根本触发不到**（要 ML Kit 引擎真出错），所以用了临时手段：把 `recognize()` 改成直接走失败分支 → 构建 → 装机 → 点快门 → 截图确认 → **移除临时代码 → 重新构建装机**。

确认还原干净（`grep TEMP-FORCE-FAILURE` 无残留、正常失败路径仍在），并且还原后 `recognized 16 lines` 正常、无崩溃。

## 遗留

文案渲染的是不带方括号的 `OCR 识别失败`。用户原文写的是 `[OCR 识别失败]`，按「方括号只用于界定字符串」理解。
