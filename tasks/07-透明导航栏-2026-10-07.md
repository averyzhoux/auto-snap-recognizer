# 07 · 全屏尝试与回退：透明导航栏

| | |
|---|---|
| **日期** | 2026-10-07 |
| **状态** | ✅ 已完成（方案经一次回退） |
| **涉及文件** | `MainActivity.kt` |

## 目标（变更过两次）

1. 最初：「变成全屏显示」→ 隐藏状态栏 + 导航栏的沉浸模式
2. 改口：「不必全屏了，只需要让这个 app 在这个红米 turbo4 运行的时候，下方控制栏的颜色是透明的就行了，可以保持状态栏，这样总归简单吧」

## 做了什么（最终方案）

- **只把底部导航栏做透明**，状态栏保留：
  ```kotlin
  enableEdgeToEdge(navigationBarStyle = SystemBarStyle.dark(android.graphics.Color.TRANSPARENT))
  ```
- **删掉底部控制栏的深色渐变衬底**，让按钮直接浮在取景画面上
- 保留导航栏避让（`WindowInsets.navigationBars`），控件待在透明导航栏上方
- 顶部胶囊只做状态栏避让（`WindowInsets.statusBars`）

## 关键决策

回退全屏是**对的**。全屏那版引入了这些问题，收益却不明显：

- 需要 `onWindowFocusChanged` 里重新隐藏（从通知栏/多任务回来时系统会把状态栏还回来）
- 内容会顶到挖孔摄像头下面，得改用刘海避让
- 用户只是想「底部别有一条黑边」，全屏是过度设计

## 踩坑

1. **`android.graphics.Color` 和 `androidx.compose.ui.graphics.Color` 同名**。`Color.TRANSPARENT` 会解析到 Compose 那个（没有这个常量）。用全限定名 `android.graphics.Color.TRANSPARENT` 绕开——**不要**为此加 `import android.graphics.Color`，那会把 Compose 的 `Color` 全搞乱。
2. Compose 的 `WindowInsets` 扩展属性（`safeDrawing` / `displayCutout`）在当前依赖组合下解析不出来（`Unresolved reference`），而 `statusBars` / `navigationBars` 可以。当时为了全屏还手写过一个用原生 `systemWindowInset*` 读 insets 的 Composable，回退后一并删掉了。

## 验证

截图确认：状态栏正常显示，底部导航栏区域透明，取景画面延伸到底，控制栏无黑底。

## 遗留

`enableEdgeToEdge` 本身保留了——它让内容延伸到系统栏后面，是透明导航栏的前提。
