# 02 · 加拍照按钮，把当前帧抓成 Bitmap

| | |
|---|---|
| **日期** | 2026-10-06 |
| **状态** | ✅ 已完成 |
| **涉及文件** | `MainActivity.kt`（Manifest 与依赖无需改动） |

## 目标

点一下按钮拍一帧，拿到 `Bitmap`，确认「真的抓到了这一帧」。

## 做了什么

- `ImageCapture` 用例与 `Preview` 一起 `bindToLifecycle`
- `onImageCapturedCallback` → `image.toBitmap()`
- 状态机 `CaptureStatus`：`Idle` / `Capturing` / `Captured(bitmap)` / `Failed(msg)`
- 底部圆形快门按钮 + 左下角缩略图 + 顶部状态条

## 关键决策

- `CAPTURE_MODE_MAXIMIZE_QUALITY`——这是**拍照模式**，不是连续预览分析。按需求「点按钮才识别一帧」，省电也避免频繁比对。
- 抓到的帧**缩放后**再进状态（当时缩到 160px 宽），不把 12MB 的全分辨率位图挂在 UI 状态里。
- 提前把 `imageProxy.imageInfo.rotationDegrees` 抄出来打日志，为第 3 步铺路。

## 踩坑

1. **`image.close()` 必须在 `toBitmap()` 之后**。顺序反了会抛 `IllegalStateException: Image is already closed`。`toBitmap()` 是拷贝像素，所以关掉之后 Bitmap 依然有效。
2. 回调执行在 `captureExecutor` 线程，**不是 UI 线程**。里面直接写 Compose state 没问题（快照写入线程安全），但不要碰 View。
3. **拍完必须给用户反馈**（缩略图 + 状态条）。少了反馈会以为没拍到，然后连点按钮——这是调试期最浪费时间的地方。
4. 这台机器拍出来是 `3072x4096`（约 12MB），1 秒一帧的话内存压力很大，后面专门处理过。

## 验证

- logcat：`captured 3072x4096, rotation=0`
- 截图确认缩略图显示正确

## 遗留

代码里那个 `rotationDegrees` 当时只打了日志、**没有真正用在像素上**——`toBitmap()` 返回的是传感器方向的原始像素（缩略图里键盘是「躺着」的）。真正的摆正放在第 3 步做。
